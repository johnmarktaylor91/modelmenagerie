A BLOCKED prerequisite is a fact about the world, proven from frozen bytes. An import statement in source
code proves only that the code imports the name -- never that the routed environment lacks the

RANDOM-INITIALIZATION AND EXECUTION POLICY
- Explicitly disable every pretrained, weights, and checkpoint flag. In an R1 declarative recipe the
  mechanism is implementation.library_recipe.pretrained_disable_fields, and it is checked, not read:
  every name in it must also be a key of library_recipe.kwargs carrying a disabling value (null, false,
  "", "none", or "random"), names must not repeat, and each name must be a real keyword parameter of the
  pinned constructor -- a name absent from that signature is refused when the recipe is loaded. So you
  cannot invent a field to fill the array. R1 requires a POSITIVE disposition and refuses silence, which
  means exactly one of two spellings: a non-empty pretrained_disable_fields naming EVERY such keyword the
  constructor exposes, or "pretrained_fields_absent": true with an empty array when the pinned
  constructor genuinely exposes none -- MiniMaxForCausalLM(config), a GNN layer, an SNN. Do not report
  BLOCKED for that case; assert absence, which is a normal, accepted R1. The assertion is verified, not
  believed: the driver reads the real constructor signature when the recipe is loaded and refuses the
  recipe if it exposes any pretrained keyword after all. Two further checks need no declaration from you
  and cannot be talked past -- a kwargs key naming a known pretrained keyword with an enabling value is
  refused outright, and a pretrained keyword left at an ENABLING DEFAULT you never mentioned
  (encoder_weights="imagenet") is refused at load. Read the signature; disable what it exposes.
- Do not download or read a checkpoint. If construction requires one, report BLOCKED at constructor with
  reason requires-checkpoint.

  phone-home list; a typed adapter must never re-enable an online check, and a recipe needing an offline

  declare train only when it is genuinely meaningful AND probe with batch >= 2.

EVERY CLAUSE IS A CLAIM -- SWEEP BEFORE YOU WRITE
The checker verifies prose CLAUSE BY CLAUSE, and the largest repair class in the pilot gate ledger is a
description, website, tag, or contract clause that outran its evidence. Before writing result.json,
re-read every sentence you authored in external_metadata.description, key_contribution, the website
prose, tags, and each taxonomy leaf, and ask of each architectural noun phrase: WHICH BOUND EXCERPT
STATES THIS? "All-MLP decoder", "encoder-decoder CNN", "batch normalization", "transformer",
"one-stage detector" -- each is refused unless an excerpt tagged with that claim's category states it;
a class name or general knowledge of the family grounds nothing. Delete or narrow any clause no excerpt
states: a shorter grounded description always beats a richer refused one. Six claim families are each
checked to their own standard; each is stated here in the checker's live terms, and each is a pass of its own:
- DESCRIPTION, WEBSITE, KEY_CONTRIBUTION: sweep every prose field clause by clause. Each factual clause --
  layer count, channel schedule, head type, class count, variant identity ("shipped unmodified by timm"),
  pooling, activation -- needs an excerpt tagged for THAT field; every factual clause of the website
  tagline, paragraph, and key-contribution line must be covered by a website-tagged excerpt. A clause you
  cannot bind is a clause you delete; a general family description carrying one unbound variant detail is
  cannot-verify for the WHOLE field. Do not strengthen the source's wording: "easier to optimize" is not
  "optimizes easily".
- TAG ARRAYS (tags, taxonomy.architecture_tags, taxonomy.novel_ops): every ELEMENT needs a field-tagged
  excerpt that names it -- dataset tags such as "imagenet" included; "metaformer", "vision-backbone",
  "bert", "swin-transformer" must each appear in a bound excerpt. Tags do not get the keywords relevance
  exception. An array with one unbound element fails whole; drop the element.
- LINEAGE and PREDECESSORS: every entry needs its own bound excerpt, and only one kind of excerpt grounds
  it -- one naming the antecedent work in an explicit derivation relation, in the source's own words:
  "based on", "extends", "modifies", "adapts", "builds on", "successor to", "inspired by". An excerpt that
  classifies the model into a family ("X is an encoder-decoder transformer", "a residual bottleneck"),
  names a baseline, or places two models in one module supports family or architecture_class only and is
  REFUSED as lineage. If no such sentence exists in the frozen sources, record the typed availability
  state ({"status": "none-exist"} or {"status": "not-found-after-search"}) -- never a guess from
  resemblance and never an empty array without that declaration.
- PARADIGM, MODES, ARCHITECTURE_CLASS: paradigm=supervised-learning needs an excerpt that literally states
  supervised training or labeled data -- a benchmark result or "trained end to end" is not proof.

  line that names the divergent layer TYPE (BatchNorm2d, Dropout, an explicit mode branch in forward)
  and, where a config flag gates that branch, the excerpt fixing the flag's value for the constructed
  object; training-procedure behavior that leaves the traced forward unchanged is not divergence.
  architecture_class needs a code or paper line showing the defining operator (a convolution, an
  attention block), not a class name or a comment.
- INPUT_CONTRACT is ONE gated claim covering everything it asserts, and every leaf of it is a checked
  claim: shape, dtype, device placement, value range or generator, normalization, mask and

- ROUTED-ENVIRONMENT CLAIMS: state that a package is installed in, or disclosed by, the routed

EXCERPT MECHANICS -- THE FIVE WAYS A TRUE QUOTE STILL DIES
1. Locator drift. The locator is verified against the FROZEN bytes, not your memory of the page:
   re-read the line number out of the stored source before recording it, and re-verify every locator
   after any later edit to the facts file. A perfect excerpt at a stale line is a locator failure, and
   it takes every claim bound to it down with it.
2. Undeclared source_id. Every excerpt's source_id must name a row of the frozen source manifest that
   you also list in source_resolution.sources. An excerpt citing an undeclared source grounds nothing.
3. Invisible bytes. ar5iv pages carry U+2003 between author names and U+00A0 before <cite> tags and
   after abbreviated author initials; some repo files use CRLF endings. A visually identical retype is
   a byte mismatch. Extract regions programmatically from the frozen bytes, then re-extract every
   excerpt back OUT of your own facts file and confirm each appears in its source verbatim -- all of
   them, not a sample.
4. Reflowed tables. ar5iv renders each table cell as its own span, so a table ROW is never contiguous
   bytes and a per-variant config row can never be excerpted from a paper table. Ground stage, width,
   and depth claims on pinned constructor source; quote papers only at prose lines.
5. Summarizer output. A web-fetch or search summary is not bytes, and it silently fabricates table
   numbers and code behavior. Use summaries to locate sources; quote only frozen CAS bytes.

UNKNOWN IS HONEST, BUT IT IS A TYPED CLAIM -- BARE NULL NEVER PASSES
A bare null or empty gated field is refused outright. If a fact genuinely cannot be established, empty the
field AND declare it in external_metadata.availability.<key> as
{"status": "not-found-after-search" | "not-applicable" | "none-exist", "values": [], "basis": <one of:
machine-derived, stated-in-paper, stated-in-code, stated-on-website, derived-from-affiliation, judged,
search-exhausted, not-applicable>, "evidence": [<evidence_ids>]}. A not-found or none-exist state
additionally requires your bounded search_report to record the queries you actually ran, so an unanswered
field is distinguishable from an unfilled one -- emptying fields is never a way to spend less effort.
BOTH "status" AND "basis" ARE CLOSED ENUMS, matched by exact string equality and declared as `enum` in the
registered schema. Copy a member; never coin a phrase that describes what you did. The single most common
way to lose a model here is writing an accurate-sounding basis that is not a member -- "bounded-source-read"
and "bounded-frozen-source-read" both killed a model on its one and only attempt. An absence you established
by reading the frozen sources and finding nothing is "search-exhausted", however the looking was actually
done; there is no separate basis for "I read the manifest".
Availability states exist for authors, institution, country, era, field, subfield, venue, year, license,
lineage, predecessors, taxonomy.era, and taxonomy.novel_ops -- and for NOTHING else: the register is a
closed schema, so a key outside that list (external_metadata.availability.original_framework, say) is
refused whole. The last four take the FULL claim path or the field name exactly as listed: lineage,
predecessors, and the literal keys "taxonomy.era" and "taxonomy.novel_ops" -- "taxonomy.era" is a
DIFFERENT record from "era", which covers external_metadata.era only.
NOTHING may be empty without a declaration. If a model genuinely has no predecessors, no lineage, or
introduces no novel operator, that is a FINDING, and you record it as {"status": "none-exist", "values": [],
"basis": "search-exhausted", "evidence": [...]} plus the bounded search that establishes it. "none-exist"
means the fact does not exist; "not-found-after-search" means you could not establish it. They are different
answers and the catalog records which one you gave.
For taxonomy.novel_ops under a library recipe, none-exist is a claim about the EXECUTED code: freeze and
cite the implementation module that actually runs (the library's `_senet` source file, not the wrapper's
docs) in the availability record's evidence before asserting no novel operator exists. An asserted
none-exist over code you never froze is refused, and a model whose introducing work names its own new
block or operator takes that grounded value instead.
A not-found claim for a fact your own pinned evidence states is a false claim and the checker is directed
to catch it.
AND THE SAME RULE GOVERNS EVERY REPAIR YOU ARE ASKED TO MAKE. A checker finding that says to remove, drop,
retract, or not assert a gated value is only half an instruction: emptying the field alone is refused as an
ungrounded claim. Ground the value, or empty it AND declare the typed availability state with its bounded
search. "The checker told me to remove it" is not a third option, and taking it is a dead record.

DECLARING A TYPED ABSENCE ALSO DISCHARGES THAT CLAIM'S EVIDENCE COVERAGE
There is no excerpt that says a fact is not there, so a claim carrying a valid absence state does not also
need an excerpt tagged with it. Every evidence_id the absence record cites must be a real excerpt you
supplied. If you would rather tag an excerpt as well, you may -- but then the excerpt's supports array must
name the claim, because coverage is read off the supports arrays and the availability record, and off
nothing else.

ORIGINAL_FRAMEWORK IS THE MODEL'S OWN PROVENANCE -- AND IT HAS NO AVAILABILITY KEY
external_metadata.original_framework names the framework of THIS architecture's introducing work. For a
wrapper-library build (smp, timm, transformers) it is never the library's framework, and for a composite
model it is never the encoder's or backbone's: a PAN built on an se_resnet50 encoder takes PAN's own
provenance, and SENet's Caffe grounds nothing about PAN. Ground it only in the introducing work itself or
the authors' own release; a third-party reimplementation never counts. Most pre-2019 papers name no
toolbox at all -- that is the expected finding, not a research failure. Because the field is a required
string with NO key in the availability register, an absence is spelled IN BAND: write the exact sentinel
"not-found-after-search" as the value, tag one excerpt from the paper's implementation-details region
(the passage that would have named a toolbox and does not) with the exact string
"external_metadata.original_framework" in its supports, and record the framework queries you ran in
search_report.queries. Never borrow the encoder's or the library's framework to dodge the sentinel; the
checker verifies the claim against the model's own work, and this exact borrow is a recurring repair.

Judgment values -- country, era, field, subfield, taxonomy leaves, paradigm, and the like -- are judged by
the Codex checker rather than by literal token overlap, since an ISO code or an era bucket is an inference
about a source rather than anything a source says. They are still mandatory, still need supporting
evidence_ids, and are still refused if wrong. Taxonomy is gated PER LEAF: every excerpt supporting your
taxonomy must name the exact leaf it supports (taxonomy.family, taxonomy.domains, taxonomy.tasks,
taxonomy.modalities, taxonomy.era, taxonomy.architecture_tags, taxonomy.novel_ops); an aggregate
"taxonomy" label covers nothing.

The citation is gated whenever the introducing paper is a fetched source, not only when you volunteer one,
and its VALUE is checked PER LEAF: title, venue, year, each author, and any declared arXiv/DOI/OpenReview ID
must occur verbatim in your paper excerpt (Unicode-canonicalized, so diacritic and ASCII spellings of one
name both ground), and a supplied bibtex must be exactly consistent with those grounded leaves. The text
searched is EXACTLY the excerpts you listed in citation.source_evidence_ids concatenated -- the rest of the
fetched page is never read, so a value that appears twenty-eight times elsewhere in bytes you hold still
grounds nothing until you bind the line that carries it. The one tolerance: an arXiv ID mentioned with a
revision selector (arXiv:2111.11418v3) grounds the unversioned ID, since the version names a revision of
that same work; the reverse is not true, so do not declare a version a bound excerpt does not show. With the
paper in hand, "no citation" is a false claim and is refused. Per-leaf VALUE checking is not per-leaf
TAGGING: the excerpt that grounds the citation must carry the aggregate string
"external_metadata.citation" in its supports array. "external_metadata.citation.title" covers nothing.

   "external_metadata.citation.arxiv_id"; "external_metadata.modes", never
